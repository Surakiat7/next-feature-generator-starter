# Internationalization (i18n)

i18n is **optional** and not installed in the base starter. It uses
[next-intl](https://next-intl.dev) and is managed entirely by the generator.

## Enable / disable

```
pnpm gen i18n init     # interactive: locales, default locale, prefix
pnpm gen i18n init --locales th,en --default-locale th
pnpm gen i18n remove   # destructive; confirmation defaults to NO
```

`init` installs `next-intl`, creates `src/i18n/{routing,navigation,request}.ts`,
`src/proxy.ts` (Next 16 renamed Middleware → **Proxy**), `locales/<locale>.json`,
a `LocaleSwitcher`, wraps `next.config.ts` with the next-intl plugin, and
migrates existing pages under `src/app/[locale]/`.

## Rules

- **Navigate with the i18n helpers**, not `next/link` / `next/navigation`:

  ```ts
  import { Link, redirect, useRouter, usePathname } from "@/i18n/navigation";
  ```

  Combine them with semantic `paths.*` — do not hardcode `/th/...`.
- Add copy to `locales/<locale>.json` and read it with `useTranslations` /
  `getTranslations`. Keep keys **static string literals** (`t("title")`).
- **Avoid dynamic translation keys** (`t(someVar)`). They cannot be statically
  analyzed, and `gen i18n remove` will refuse to run if any exist.
- The feature/page generators are i18n-aware: after `init`, the same
  `pnpm gen page …` command emits pages under `src/app/[locale]/…`
  automatically. Do not learn a different command.

## Removal safety

`gen i18n remove` scans usage first, reports counts, and:

- **Aborts** if a dynamic translation key is found (no files changed).
- Otherwise inlines simple static `t("key")` calls from the default locale,
  restores the non-localized app structure, and uninstalls `next-intl`.
